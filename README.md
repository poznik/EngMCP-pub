# EngMCP

Локальный MCP-сервер для Windows x64. Подключает Codex Desktop, Claude Desktop и DeepSeek Harness Desktop к Jira, Confluence Data Center, GitLab, Jenkins и Allure TestOps. Один фоновый процесс обслуживает клиентские сессии, хранит реквизиты через Windows DPAPI и проверяет разрешения на каждую операцию.

## Установка

1. Запусти `EngMCP-Setup-x64.exe` из [выпусков проекта](https://github.com/poznik/EngMCP-pub/releases). Установщик работает с правами текущего пользователя. Автозапуск при входе включается по желанию.
2. Открой «Настроить EngMCP» из меню «Пуск». На чистой установке видны пять вкладок сервисов. Для прямого подключения их API должны быть доступны с компьютера, например через VPN.
3. На вкладке Jira или Confluence укажи базовый адрес сервиса с его путём контекста и отдельный PAT. Включи модуль и нужные операции. Сохрани и нажми «Проверить сохранённое подключение». Панель покажет учётную запись сервиса.
4. Для GitLab, Jenkins или Allure TestOps открой вкладку сервиса и укажи базовый адрес экземпляра, включая путь контекста. Для GitLab нужен PAT с областью `read_api`, для Jenkins — имя пользователя и API-токен этого пользователя, для Allure — персональный API-токен. Включи модуль и нужные операции, сохрани и проверь подключение. Новые модули по умолчанию выключены.
5. В разделе «Подключение клиентов» выбери Codex Desktop, DeepSeek Harness Desktop или Claude Desktop. Наведи указатель на фрагмент и нажми значок копирования в правом верхнем углу. Вставь фрагмент в конфигурацию клиента и полностью перезапусти клиент. Для Claude Desktop панель показывает запись `engmcp` для раздела `mcpServers` в `%APPDATA%\Claude\claude_desktop_config.json` с путём к установленному приложению.

### Дополнительный шлюз для Jira и Confluence

Если для доступа нужен NetScaler nFactor, получи совместимый компонент у своего администратора. Установи его вместе с зависимостями рядом с `engmcp.exe` в `engmcp-gateway/engmcp-gateway.exe`. После обновления страницы появятся вкладка «Шлюз 2FA» и выбор режима у Jira и Confluence. Введи в профиле шлюза HTTPS-адрес, логин, пароль и постоянный Base32-ключ TOTP. На вкладке нужного сервиса выбери режим «Через шлюз NetScaler (2FA)».

## Что можно попросить у клиента

| Пример запроса | Инструмент | Результат |
| --- | --- | --- |
| Найди тикеты со словами «ошибка оплаты» | `jira_search_text` | Страница кратких результатов текстового поиска Jira |
| Выполни мой JQL `filter = 12345 ORDER BY updated DESC` | `jira_search_jql` | Страница готового запроса, включая сохранённый фильтр по ID |
| Прочитай задачу DEMO-12 | `jira_get_issue` | Описание, статус, исполнитель, связи и другие основные поля |
| Получи все поля DEMO-12 | `jira_get_all_fields` | Полный ответ Jira с `fields=*all` и `expand=names,schema`, включая пользовательские поля |
| Найди страницы Confluence по `type = page AND space = DEV` | `confluence_search_cql` | Страница выдачи CQL, параметры `start` и `limit` |
| Прочитай страницу Confluence с ID 42 | `confluence_get_page` | Тело в формате storage, версия и пространство |
| Найди проекты GitLab по имени | `gitlab_list_projects` | Доступные проекты с числовыми ID |
| Покажи merge requests проекта или открой MR №7 | `gitlab_list_merge_requests`, `gitlab_get_merge_request` | Список MR или карточка по паре `project_id` и `iid` |
| Покажи состояния пайплайнов проекта | `gitlab_list_pipelines` | Страница пайплайнов GitLab |
| Перечисли задания Jenkins в папке QA | `jenkins_list_jobs` | Имена и ссылки на доступные задания |
| Найди последние сборки задания или результат сборки №9 | `jenkins_list_builds`, `jenkins_get_build` | Номер, результат, время и длительность |
| Перечисли запуски тестов проекта | `allure_list_launches` | Страница запусков Allure TestOps |
| Открой запуск или тест-кейс по ID | `allure_get_launch`, `allure_get_test_case` | Карточка объекта из Report Service |

GitLab принимает числовой ID из списка проектов, `page` с 1 и `per_page`. Для Jenkins поле `job` содержит полное имя задания с папками, а `start` — смещение с нуля в текущей коллекции. В Allure страницы начинаются с 0, параметр размера — `size`. Размер запрашиваемой страницы по умолчанию 25, максимум 100. [GitLab REST API](https://docs.gitlab.com/api/rest/) · [Jenkins Remote Access API](https://www.jenkins.io/doc/book/using/remote-access-api/) · [API Allure TestOps](https://docs.qameta.io/reference/api/)

Поиск Jira принимает `start_at` и `max_results` от 1 до 100 для размера страницы. Следующее смещение вычисляется как `startAt + len(issues)`, пока оно меньше `total` и в выдаче есть задачи. Клиент может разбить сложный запрос на подбор JQL и выполнение готового выражения. Доступность полей и задач определяет учётная запись Jira. Вложенные коллекции, для которых Jira возвращает только первую страницу, сохраняют пагинацию исходного API.

## Настройки и журналы

- Данные пользователя находятся в `%LOCALAPPDATA%\EngMCP`. В `settings.json` PAT каждого сервиса, пароль шлюза и TOTP-ключ зашифрованы через Windows DPAPI для текущего пользователя. При смене адреса шлюза или логина пароль и ключ вводятся заново. При смене базового адреса подключению требуется новый токен. Для Jenkins он также привязан к сохранённому имени пользователя.
- В `logs\audit-*.jsonl` записываются изменения настроек, вызовы и отказы. В `logs\diagnostic-*.jsonl` видны этап, код HTTP, объём ответа, длительность и идентификатор запроса. Тексты задач, JQL и токены исключены из журналов.
- Срок хранения задаётся в панели, по умолчанию 14 дней. Изменения прав действуют в открытых сессиях со следующего вызова. Уже отправленный в Jira запрос может завершиться.
- На всех вкладках восемь звёздочек показывают, что токен, пароль или TOTP-ключ уже сохранён. Чтобы заменить его, введи новое значение. Если оставить поле без изменений, текущие реквизиты того же подключения сохранятся.
- Удаление приложения останавливает процесс, убирает файлы приложения и ярлыки. Пользовательские настройки и аудит сохраняются.

## Сборка и проверки

Для сборки установщика на Windows x64 нужны Go версии из `go.mod`, Python 3.10+ и Inno Setup 6. Команда `.\build.ps1 -BinaryOnly` собирает сервер и панель с помощью одного Go.

```powershell
.\build.ps1
go vet ./...
python -X utf8 tests/smoke.py
```

Сборка создаёт `dist/engmcp.exe` и `dist/EngMCP-Setup-x64.exe`. Базовый сквозной тест использует стандартную библиотеку Python, отдельный профиль и локальную фикстуру Jira. Он проверяет две одновременные сессии, отзыв прав, журналы и бюджеты производительности.

Дополнительные прогоны описаны в [инструкции проверки](docs/verification.md). Принятые решения, границы прототипа и дальнейшие этапы — в [архитектуре](docs/architecture.md).
